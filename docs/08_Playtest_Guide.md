# 08 · 试玩指南（种子试玩 · Alpha）

## 这次试玩要回答的问题

1. **会不会无聊？** 战役中段有没有"只是在按回车"的感觉，出现在第几个月。
2. **看不看得懂输赢？** 输了之后，玩家能不能用自己的话说出原因（天时、地利还是人和）。
3. **想不想再来一局？** 结束后是否主动要求重玩或换一个选项试试。

三个问题都过关，才进入 Beta（补齐案例四到九）。任何一个不过关，先改核心循环。

Alpha 种子试玩（0.6.0 起）另外要回答两个问题：

4. **危机公关指挥室**：24 小时三次决断，节奏够不够紧张？玩家是否注意到「门派高管坐镇才全额生效」？
5. **自由沙盒**：玩家能不能自己找到「招人 → 选址开店 → 关掉亏损店」的循环？在第几年开始失去目标、想离开？

---

## 招募

- **人数**：5–10 人，每人约 45 分钟。
- **构成**：
  - 2–3 名策略/经营类游戏玩家（玩过大亨类、P社、文明系列）
  - 2–3 名几乎不玩策略游戏的人
  - 1–2 名对奇门、风水或创业有了解的人
- **不要**招募参与过开发、已经知道"正解"的人。

## 网页版试玩（推荐）

网页版不需要安装，发一个链接即可，也方便远程试玩：

1. 用 `tools/publish_web.sh --push` 发布到 itch.io（页面可设为 Restricted，只有拿到链接或密码的人能玩），把链接发给试玩者。
2. 请试玩者用**电脑上的 Chrome 或 Edge** 打开，打开声音。首次加载约 90 MB（0.7.0）。
3. 试玩数据默认记录在试玩者自己的浏览器里，不会自动上传。玩完后请试玩者在结局画面（或「设置」）点 **「导出试玩记录」**，把下载的 `dynasty_tycoon_playtest_日期.jsonl` 发回。
4. 远程试玩无法现场观察时，请试玩者录屏或边玩边语音，访谈改为玩完后的视频通话。

记录字段与终端版相同（开局决断、各议题选择、期末现金等），另含办公室风水评分，可以和下面的观察记录一起汇总。

## 终端版准备

```bash
cd dynasty_tycoon
python3 play.py --playtest
```

`--playtest` 会把每局战役的开局决策、每个决策点的选择和结局写入 `saves/playtest_log.jsonl`（每局一行）。每位玩家开始前，把上一位的记录文件改名保存，例如 `playtest_log_玩家3.jsonl`。

终端窗口建议至少 100 列宽，字号调大。

## 流程

### 种子试玩（网页版 0.6.0，约 70 分钟）

| 时间 | 内容 |
|---|---|
| 0–3 分钟 | 一句话介绍："这是一个用奇门遁甲做规则的商业经营游戏，你是董事长。" **不要解释规则**。 |
| 3–20 分钟 | 战役一（新中式烘焙）。 |
| 20–28 分钟 | 案例十 · 危机公关 24 小时（一局约 5 分钟，失败了可以马上再来一局）。 |
| 28–55 分钟 | 二十年自由沙盒：自选行业开局，**至少玩到 2027 年**，之后想停就停（可以「提前封盘结算」）。 |
| 55–70 分钟 | 访谈（见下方问题）。时间富余时补战役三。 |

远程试玩者自己按这个顺序玩，玩完点「导出试玩记录」把文件发回。

### 终端版（约 45 分钟，Milestone 0 验收用）

| 时间 | 内容 |
|---|---|
| 0–3 分钟 | 同上，一句话介绍，不解释规则。 |
| 3–20 分钟 | 战役一（新中式烘焙）。 |
| 20–35 分钟 | 战役三（创业四人组）。战役二较难，只给提前完成的玩家。 |
| 35–45 分钟 | 访谈。 |

### 主持人守则

- 请玩家**边玩边说出想法**（"我选B是因为……"）。
- 玩家提问时只回答"你觉得呢？"，除非卡住超过 2 分钟。
- **不要**在玩家读完解读之前催促推进。
- 输了不要安慰或解释，直接进入访谈，听玩家自己怎么解释。

## 访谈问题

**核心三问（必问）**

1. 刚才这局你觉得哪一段最无聊？哪一段最紧张？
2. （输了的玩家）你觉得为什么没通关？（赢了的玩家）你觉得自己哪个决定最关键？
3. 如果现在可以再玩一局，你想玩吗？会换哪个选择？

**补充问题**

4. 月度解读里的"旺相休囚死"你看懂了吗？对你的决策有没有帮助？
5. 有没有哪个决策点的结果让你觉得"不公平"或"莫名其妙"？
6. 八门高管（景门、伤门、杜门……）的性格差异你感受到了吗？
7. 用 1–5 分评价：好不好上手 __ / 决策有没有分量 __ / 题材有没有吸引力 __

**危机公关与沙盒（种子试玩加问）**

8. 危机公关的 24 小时里，哪一次决断最难？你是看什么做的决定（怒火、信任、花费，还是文案）？
9. 沙盒里你给自己定了什么目标？什么时候觉得"差不多了"？
10. 人才市场雇人时，你看的是要价、门派，还是"人和"系数的变化？
11. 如果沙盒要加一样东西让你愿意玩满二十年，你希望是什么？

## 汇总时看什么

把试玩者发回的记录放进同一个目录（**`playtests/` 已加入 .gitignore，试玩数据不会被提交**），每人一个文件、文件名用代号（如 `玩家3.jsonl`），然后：

```bash
python3 tools/analyze_playtests.py playtests/ --out playtests/报告.md
```

报告按战役、危机公关、自由沙盒分别列出结局分布、中途退出的位置、每个选项被选的比例和对应通关率，并在开头「需要关注」里自动标出：几乎没人选或高度集中的选项、退出率过高、通关率过高或过低、沙盒里没雇高管的局。战役还会对照「不计随机事件时可通关的路线」，区分"选对了却输给运气"和"选错了却被运气救了"。同一试玩者多次导出的重复记录会自动去掉。

想先看报告长什么样，可以用游戏生成一批模拟记录：

```bash
godot --headless --path godot -s res://tests/gen_playtest_samples.gd -- /tmp/模拟试玩 8
python3 tools/analyze_playtests.py /tmp/模拟试玩
```

自动统计只回答「做了什么」，下面这些要结合观察记录与访谈：


- **无聊月份**是否集中在没有决策点的月份。如果是，说明需要更多中段决策点或其他可操作的事。
- **输因复述**：能说对原因的人少于一半，说明解读文案或反馈不够清楚。
- **再玩意愿**：少于一半的人想再玩，说明核心循环本身有问题，要先修这个，再补关卡。
- 把 `playtest_log_*.jsonl` 汇总，看大家的选择是否高度集中在某个选项。如果某个选项几乎没人选，可能是文案让它显得明显很差，也可能是它真的太弱。

工程侧可以用下面的命令对照每条路径在不考虑随机事件时的结果：

```bash
python3 tools/campaign_paths.py 1 3
```
